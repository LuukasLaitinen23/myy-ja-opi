# About

This project entails a marketplace application intended primarily for university students. Items that can be sold include work laptops, overalls badges or tickets to student events.

# Git practices

Before pushing new commits, the developer should test that the code works first. A commit does not have to be fully finished or flawless to be applicable for submission, however in such cases the developer should push into a separate branch instead. Commits should be kept relatively small to ensure changes can be easily reverted.

As mentioned above, every new feature should be implemented in a separate branch. Once a new feature is stable and finished, it can be merged with main. Main branch should always be kept stable.

When merging to main, at least two developers should handle the merge together. This ensures merge conflicts will be handled with care and that the code stays stable.

Commit messages should follow the standard for best practices, first indicating the type of change followed by a description of what was changed written in the present tense. Messages should be kept easily understandable by other group members.
